# DNSCrypt-Proxy 2 Forge 0.1.3-r1

This release extends [ewgen198409/luci-app-dnscrypt-proxy2](https://github.com/ewgen198409/luci-app-dnscrypt-proxy2) with multiple instance support, detailed startup and restart output, and safer configuration saving.

Prepared on **2026-09-29**. Built and tested for **OpenWrt 24.10.1**, **GL.iNet GL-MT6000**, mediatek/filogic, aarch64_cortex-a53.

Added a separate **OpenWrt 25.12.5 APK build** for the same target. Package contents and metadata are verified; runtime testing on OpenWrt 25.12.5 is pending. The existing IPK remains the package for OpenWrt 24.10.1. Required dependencies and LuCI APIs are present in OpenWrt 23.05.5, but installation and runtime behavior on that version have not been tested.

## Added compared with upstream

- Added discovery and selection of separate `dnscrypt-proxy*` services. Each instance uses its own TOML configuration, resolver list, log source, and service controls.
- Added a shared instance table with service status, listen addresses, and configuration paths, with status updates every 10 seconds.
- Added discovery of stopped services through literal `PROG` and `CONFIGFILE` assignments in init scripts, without executing them.
- Added an operation output panel for start, stop, restart, and Save & Apply. It displays command output and new DNSCrypt messages, including resolver names and latency when available.
- Added startup monitoring for up to 20 seconds. The interface checks command exit status and reports process state, confirmed readiness, startup failure, or unconfirmed readiness.
- Added a dedicated RPC endpoint for syslog output filtered by the selected process ID, including the previous process ID during a restart.
- Added support for configuration files in subdirectories and log paths resolved relative to the selected TOML file.
- Added a separate Forge package and menu entry so the interface can coexist with the original package.

## Configuration and reliability fixes

- Changed form saves to update only edited fields, preserving untouched parameters, comments, and TOML sections such as `sources`, `static`, and `anonymized_dns`.
- Added detection of configuration changes made outside the page before saving.
- Added unsaved-change warnings when switching instances and guards against conflicting form and raw-editor changes.
- Fixed instance selection reverting to the second instance after navigation or reload.
- Fixed numeric field handling so valid zero values are not replaced with defaults.
- Fixed relative log paths for configurations stored in subdirectories.
- Disabled service actions when multiple procd instances share one init service, preventing an apparently individual action from controlling all of them.
- Removed the inherited Redirect DNS shortcut from the form. DNS/DHCP and failover configuration remain separate from instance management.

## Security and text-integrity fixes in 0.1.3

- Fixed initial TOML rendering decoding HTML entities such as `&amp;` and `&region`. The editor now preserves literal configuration text.
- Changed configuration values, log-derived resolver names, error messages, and paths to render as text rather than HTML.
- Replaced HTML-string construction in both resolver selection dialogs with DOM cells, closing the injection path through resolver names, protocols, and addresses.
- Fixed empty-list and command-error messages in resolver dialogs to display readable text instead of a DOM object string.
- Restricted package ACLs to required configuration writes and service/list commands; removed inherited DHCP write and file-removal permissions.

## Packaging and verification

- Added a build script restricted to the OpenWrt 24.10.1 mediatek/filogic SDK and a package verifier checking the exact installed payload, source equality, metadata, and dependencies.
- Versioned frontend resource names and invalidated the LuCI index cache during installation to avoid serving stale interface code after upgrades.
- Added tests for instance discovery, isolated saves and service actions, TOML preservation, external-change guards, and process-scoped log output.
- Added browser checks using LuCI-compatible `E()` behavior. Regression cases cover literal TOML round trips, HTML entities, injection payloads, both resolver dialogs, filtering and selection, and command-error notifications.
- Verified the installed interface on the target router: instance switching and resolver lists for both services. Existing configurations, init scripts, and DNSCrypt process IDs remained unchanged during the interface upgrade.

## Installation

Verify `SHA256SUMS` and transfer the package matching your OpenWrt version to the router.

For OpenWrt 24.10.1:

```sh
opkg install /tmp/luci-app-dnscrypt-proxy2-forge_0.1.3-r1_all.ipk
/etc/init.d/rpcd reload
```

For OpenWrt 25.12.5:

```sh
apk add --allow-untrusted /tmp/luci-app-dnscrypt-proxy2-forge-0.1.3-r1.apk
/etc/init.d/rpcd reload
```

The APK uses a local SDK signing key, so installation requires `--allow-untrusted`. Its build, exact payload, metadata, dependencies, and integrity have been verified. Router runtime testing on OpenWrt 25.12.5 is pending.

Refresh LuCI and open **Services → DNSCrypt-Proxy 2 Forge**.

## Known limitations

- Only OpenWrt 24.10.1 on GL-MT6000 has been tested for this release.
- Independent service actions require separate init services. Multiple instances belonging to one service have editing access but no individual start/stop/restart controls.
- Dynamic paths in stopped-service init scripts are not evaluated.
- Raw TOML saves are not validated by the DNSCrypt binary. The external-change check does not provide a file lock.
- Resolver latency is displayed when present in DNSCrypt output; it is not a continuous independent latency measurement.
